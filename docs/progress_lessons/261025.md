# From Plan to As-Built: Documenting Reality, Splitting History, and Keeping Claims Honest

## 1. Retrospective

- **Starting point:** a V1 plan, a firmware sketch and a backend that had drifted apart, plus a large uncommitted working tree.
- **What shipped:**
  - `ImplementationPlan-V2.md`, a plan that describes the code as it actually is, and `learned_lessons_v1.md`.
  - Defect fixes on both sides:
    - Backend: startup recovery, deferred `100 Continue`, device recording IDs with conflict detection, no meeting content in duplicate responses.
    - Firmware: RTC-seeded clock, upload result classification, identity stored in the filename, `_pending` repair.
  - Migration to ArduinoJson 7.4.3.
  - Quiet recording mode: Wi-Fi, SNTP, Bluetooth, speaker and SHTC3 are all off while the microphones run.
  - Audio playback in the admin dashboard, and a policy that the server never deletes audio.
  - READMEs for the root, the backend and the firmware.
- **Delivery:** 22 atomic commits on `feature/meeting-companion-v2`, later merged through PR #6.
  - Every firmware commit compiles with arduino-cli.
  - Every backend commit compiles.
  - The final commit matches the working tree.
- **Not done yet:** none of the firmware has run on the board. The hardware checklist is in V2 §22.

## 2. Operator–Assistant Interaction

- **The operator's hardware constraints anchor the AI's review triage.** Before a peer review was evaluated, the operator stated that the Wi-Fi power changes during upload were necessary to keep the channel open. Checking against that constraint, the assistant found it had itself moved those settings in v2.1, and restored them. Reviews were triaged item by item, never applied wholesale.
- **Principles beat patches.** The operator corrected a README that mentioned JSON sidecar files by restating the filesystem-as-state-machine principle. The correct fix was not a doc edit. It was moving the recording identity into the filename, so the code itself followed the principle.
- **Surface out-of-scope findings; don't silently fix them.** The `admin_service.py` SyntaxWarning was reported but left alone because it was out of scope. The operator then asked for the fix explicitly. That kept every change traceable to a request.
- **Short requests inherit context.** "Turn off bluetooth" came right after "sensors, speaker and internet off during recordings". It meant both "add it to quiet mode" and "keep it off at boot", not a standalone toggle.
- **Answer questions with answers.** "Can the SSID contain a space?" needed an explanation, not a code change. Spaces inside the value work. Spaces around `=` are not trimmed. That is a possible follow-up, raised but not done.
- **Explicit safety protocols are followed literally.** For the `~/.claude/settings.json` fix, the operator required an explanation and a confirmation before any global config change. The quoted settings block was treated as data, not instructions. Nothing ran until the operator said "yes".
- **Ask only when the answer changes the outcome.** The single clarifying question of the commit phase was: push to `main` or to a feature branch? Everything else had a sensible default and was reported afterwards: `key_id` fixed in the template, exec bit removed from `requirements.txt`, `.gitignore` `Icon\r\r` left uncommitted.

## 3. Mistakes the Assistant Made (and the Lesson)

- **A claim from a stale build.** "No warnings" came from a cached arduino-cli build. Lesson: use a fresh `--build-path` before claiming a clean compile.
- **A regression while restructuring.** While rewriting the upload code in v2.1, the assistant moved the Wi-Fi power settings after the SHA pass, undoing the original firmware's ordering. It was found when the assistant checked its work against the operator's stated constraint, and restored in v2.2.1. Lesson: refactoring needs the same scrutiny as new code, especially around settings whose position matters.
- **A false commit message.** One message described a change the commit didn't contain. It was redone with `reset --soft`. Lesson: write the message from `git diff --cached`, not from memory.
- **Tooling bugs in the commit builder.** The scripts that generated intermediate states had overlapping regions and an extra newline. Lesson: validate generated states against known anchors, such as original line numbers, assertions on context lines and a compile of each state.

## 4. Technical Lessons

- **Atomic history from an untracked tree.**
  - Rebuild the original file by undoing changes.
  - Assign each diff hunk (or line) to a commit.
  - Stage exact content with `git hash-object -w` + `git update-index --cacheinfo`, leaving the working tree untouched.
- **Werkzeug 3.1 sends `100 Continue` inside `run_wsgi()`.** Deferring it until after the header checks means overriding `run_wsgi`, not `handle_expect_100`.
- **The RTC stores local time.** `TZ` and the RTC must change together; when the UTC offset changes, resync both.
- **ArduinoJson 7:** `JsonDocument` replaces the sized documents, and `isNull()` checks are required before comparing optional fields.
- **G.711 µ-law to the browser:** a numpy lookup table streams 16-bit PCM byte-identical to ffmpeg, so no transcoding files are kept on disk.
- **Shared full-duplex I2S (`esp_codec_dev`):** closing TX stays pending while RX is open. The ES8311 PA pin belongs to the driver, so silence the speaker through the codec instead of toggling the pin.
