# A Failing SD Card, a Broken Encoder, and Measuring Instead of Guessing

## 1. Retrospective

- **Symptoms:** SD errors after idle, uploads cut off mid-body, the placeholder server address in use, `0x107` read timeouts, and a corrupted root directory.
- **Cause 1, the SD card:** the card was failing. First Aid reported success, and the Mac read every file, but `f3write` made the card drop off the bus. The operator recovered it with `diskutil secureErase 0 disk4` and reformatted it.
- **Cause 2, the "dirty audio":** a firmware bug. The µ-law encoder had not followed G.711 since 2026-10-23: 1.8 dB SNR on a test tone, against 37.9 dB once fixed.
- **Shipped:** 12 commits on `main` (`092aefc..376625d`). See the v2.5 entry in `../changelog.md`.
- **Verified:**
  - Every firmware commit compiles, and removing all of the day's changes rebuilds yesterday's file exactly.
  - 35/35 backend tests pass.
  - The operator confirmed it all works on the board.
- **Open:**
  - Repairing the µ-law recordings made before the fix.
  - A card-full warning.
  - Host tests for firmware helpers.

## 2. Operator–Assistant Interaction

- **Check the operator's pushback.** "It worked before we touched it" led to a diff and A/B builds. That check is how the invisible log lines (§3) were found.
- **Logs from both ends solve things fast.** `received 0 of 145452 bytes` and the second `0x107` log each pointed straight at the cause.
- **The operator owns protocol choices.** They chose 499 over 400. The device had to treat 499 as "retry later", or files would have been marked `_rejected`.
- **Back up before anything destructive.** The card was mounted read-only first, and its 12 files were copied and checked with SHA-256 before the reformat.
- **Measure the reference version.** The pasted "clear" sketch had the same encoder bug. The clear recordings were the 16-bit PCM ones from before µ-law.
- **Suggest the cheap repair before "replace it".** The assistant said to retire the card. The operator's zero-fill fixed it.

## 3. Assistant Mistakes

- **Invisible diagnostic output.** `Serial.printf` goes only to UART0, but the operator watched the USB console. A missing line was read as evidence when it was simply invisible. **Lesson:** check where the console goes before adding log lines.
- **A regression already recorded in `261025.md`.** A new config read before uploads ran with Wi-Fi at full power, breaking V2 §18.3. **Lesson:** check every new SD access against the radio rules.
- **Guessing too long.** Firmware defenses came before the cheapest test, a different card. **Lesson:** for physical symptoms, suggest the hardware swap early.
- **Trusting `fsck`.** It checks the filesystem structure, not the flash. **Lesson:** test the card itself with `f3write`/`f3read`.
- **A lost edit.** A default-port change vanished while the operator was staging files. **Lesson:** re-read the diff after the operator touches the index.

## 4. Technical Lessons

- **`diskutil secureErase 0 <disk>`** writes one pass of zeros over the whole device. Afterwards, format it again as MS-DOS (FAT) with a Master Boot Record.
  - **Why it helps:** unlike a quick format, it makes the controller rewrite every flash page. That refreshes weak cells and swaps out failing blocks.
  - **Limits:** it can't undo wear. Test the card afterwards and retire it at the next error.
  - **Before running it:** confirm the disk number. It erases without asking.
- **A card that timed out stays stuck** until it is unmounted and mounted again. Retry once after the remount, never with a file open.
- **Test an encoder with a round trip** over all 65,536 inputs. Tests on the decoder alone can't catch an encoder bug.
- **Measure audio:** noise floor, level, distinct µ-law codes, and steps at frame boundaries (dropped samples).
- **Read the whole file before opening an upload,** so a failed read never follows the server's `100 Continue`.
- **Keep Wi-Fi at low TX power for every SD access,** with a scoped guard outside the upload batch.
- **Flash wear comes from small writes.**
  - Write config files only when they change.
  - Buffer recordings with `setvbuf`, in internal DMA-capable RAM, not PSRAM.
  - Keep each flush shorter than the I2S DMA buffer (about 90 ms).
- **`usb_serial_jtag_is_connected()`** reports only a computer, never a charger, so it's a safe switch for development mode.
- **An open port gets scanned within minutes.** Close port forwards after testing.
- **Atomic commits from mixed hunks:** peel the features off in reverse and check that the result equals `HEAD`, compiling each step.
